## Recommended implementation sequence

1. **Small independent internal terminal surface coordinator.** Retain latest world frame (including empty) while prompt owns the raw surface; restore on prompt close. Centralize raw full-screen replacement/ownership while retaining transcript/line-mode semantics. No new module/dependency/public UI API; do not claim it implements node visibility, overlay composition or #147. This is safe useful preparation, with exact tests above. API remains renderFrame(List<String>), frames should be copied because retention is new.
2. Agree prompt activation migration and general node visibility semantics. Implement guarded local/effective visibility plus core/headless regressions. Separately migrate prompt activation API with guide/examples/compatibility policy; document no automatic pause/resume.
3. Implement node-aware terminal composition using existing surface coordinator and agreed contribution order/ownership. Retain anonymous renderFrame compatibility until callers migrate; do not silently ascribe arbitrary strings to nodes. Clear stale output via full replacement first, optimize only with evidence. Desktop remains explicitly limited until separately repaired.
4. Design spike for reactive expression capture + UI contract. Prove direct required DSL, initialization once, selective property and structural re-evaluation, retention/key identity using existing compiler/tooling or an explicitly agreed alternative. No Compose dependency/module by default.
5. Build approved first UI slice in existing engine/platform boundaries: constraints/layout Row/Column/Box, Text, Button, semantics/focus and recording backend; reuse node lifetimes and merged subscription helper. Prove differing text/cell metrics; terminal adapter owns measurement/painting only.
6. Migrate prompt editing and presentation to proven shared focus/UI facilities. Preserve command parser/definitions/validation/invocation independently; delete superseded routing/render helpers only after replacement tests/callers exist.

Keep focused PRs and explicit dependencies; #148 remains open until its later consolidation criteria are met. Full engine test/lint/build/coverage for implementation, targeted docs/site checks for public guide changes. No production behavior or test results were changed by this audit. SceneManager.kt:539-546 updateBoundary currently drains queued destruction at the outer traversal boundary; it is private and not a general pending UI mutation scheduler. A future UI scheduler must specify its own commit ordering relative to input, frame/physics traversal and deletion without exposing or repurposing this helper casually.

## Outstanding decisions

- **Activation naming:** approve prompt open/close/isOpen separate from Node.hide/show? Recommended yes, with pre-0.1 migration notes; decide deprecation aliases vs direct break after assessing Kotlin/JVM clash.
- **Surface policy:** preserve replacement-style console initially or introduce overlay? Recommended preserve replacement now, retaining latest world frame. Overlay needs agreed ordering/placement/clipping and belongs after node-aware composition.
- **Reactive syntax mechanism:** compiler capture design spike for required inline interpolation/if/for, or change accepted DSL to explicit reactive expressions? Recommend spike in existing tooling; ordinary Kotlin cannot provide the stated automatic behavior by itself.
- **UI contract:** choose logical units/cell conversion, focus ordering/eligibility, root ordinary-node integration and managed child transfer/mutation policy. Define these concretely before implementation rather than inferring from illustrative names.
